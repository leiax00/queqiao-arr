## 工作流程

当用户请求执行 smart-pr 时，按以下步骤进行：

### 1. 检查分支状态
- 执行 `git branch --show-current` 获取当前分支名
- 检查是否有未提交的变更：`git status`
- 检查是否已推送到远程：`git log @{u}..HEAD`
- 如果有未提交的变更或未推送的提交，提示用户先完成提交和推送

### 2. 分析变更内容
- 执行 `git log develop..HEAD --oneline` 查看提交列表
- 执行 `git diff develop...HEAD --stat` 查看变更文件统计
- 识别分支类型：`feature` | `fix` | `hotfix`
- 从分支名提取任务编号（如 B-07）

### 3. 代码质量检查（可选）
根据变更内容执行检查：
- **Backend**: 如果修改了 `backend/app/**/*.py`，提示是否运行检查
  - `ruff check backend/app/`
- **Frontend**: 如果修改了 `frontend/src/**/*.{ts,vue}`，提示是否运行检查
  - `cd frontend && npm run type-check`

如果检查失败，**停止 PR 流程**并告知用户问题。

### 4. 生成 PR 标题
根据 Conventional Commits 规范和分支内容生成标题：

**格式**: `<type>(<scope>): <中文描述>`

**类型选择**:
- `feat` - 新功能
- `fix` - Bug 修复
- `refactor` - 代码重构（不改变功能）
- `docs` - 文档更新
- `style` - 代码风格调整（不影响逻辑）
- `test` - 测试相关
- `chore` - 构建/工具/依赖更新
- `opt` - 性能优化
- `improve` - 功能改进或增强

**作用域选择**: `backend` | `frontend` | `api` | `docker` | `docs` | `agent`

**标题生成规则**:
- 从提交历史中提取主要变更类型和作用域
- 使用简洁的中文描述核心功能
- 如果有任务编号，在标题末尾添加 `#任务编号`
- 如果是 feature 分支，优先使用 `feat` 类型
- 如果是 fix 分支，优先使用 `fix` 类型

**示例**:
- `feat(torznab): 实现 Torznab XML 生成模块 #B-07`
- `fix(api): 修正认证中间件的 Token 验证逻辑`
- `refactor(backend): 优化数据库连接池配置`

### 5. 生成 PR 内容
根据以下模板生成 PR 描述：

```markdown
## 概述
[1-3 句话描述这个 PR 的主要目的和实现的功能]

## 变更范围
- [列出主要的模块/组件变更]
- [使用简洁的列表]
- [按重要性排序]

## 主要功能
- [功能点 1]
- [功能点 2]
- [功能点 3]

## 技术细节
- [技术实现要点 1]
- [技术实现要点 2]
- [使用的关键技术或模式]

## 测试情况
- [ ] 已通过本地后端测试
- [ ] 已通过代码质量检查（ruff/black）
- [ ] 已通过前端类型检查（如有前端变更）
- [ ] 已手动测试核心功能

## 相关 Issue
关联 Issue: #[任务编号]

## 检查清单
- [ ] 代码符合项目规范
- [ ] 已添加必要的测试
- [ ] 文档已更新（如需要）
- [ ] UI 变更已附截图（如适用）
```

**内容填充规则**:
- **概述**: 从提交信息中提取核心功能，使用简洁的中文描述
- **变更范围**: 根据 `git diff --stat` 的结果，列出修改的主要文件和模块
- **主要功能**: 从提交历史中提取功能点，按重要性排序
- **技术细节**: 提取关键的技术实现，如使用的设计模式、新增的模块等
- **测试情况**: 根据代码质量检查结果自动勾选
- **相关 Issue**: 从分支名或提交信息中提取任务编号

### 6. 展示 PR 信息
向用户展示：
- 当前分支名
- 目标分支（默认 `develop`）
- PR 标题
- PR 内容预览

等待用户确认。

### 7. 推送并创建 PR
1. 确保代码已推送到远程：
   ```bash
   git push -u origin $(git branch --show-current)
   ```
2. 使用 gh CLI 创建 PR：
   ```bash
   gh pr create --base develop --title "<PR 标题>" --body "<PR 内容>"
   ```
3. 获取并展示 PR URL

### 8. 汇报结果
向用户简洁汇报：
- ✅ PR 创建成功
- 🔗 PR 链接
- 📝 PR 标题
- 📊 变更统计（提交数、文件数、新增/删除行数）

## 注意事项

- **目标分支**: 默认为 `develop`，除非是 `hotfix/*` 分支（目标为 `main`）
- **分支命名**: 遵循 `feature/*`、`fix/*`、`hotfix/*` 命名规范
- **任务编号**: 在标题和内容中包含任务编号（如 #B-07）以便关联
- **质量保证**: 确保代码已通过必要的测试和检查后再提交 PR
- **截图**: 如有 UI 变更，提醒用户在 PR 中附上截图
