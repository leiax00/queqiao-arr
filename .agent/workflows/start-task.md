## 工作流程

当用户请求执行 start-task 时，按以下步骤进行：

### 1. 获取任务信息
从用户处获取：
- 任务编号（如 B-08）
- 可选：任务名称（如果与 TODO.md 中不同）

### 2. 读取 TODO.md
- 解析 TODO.md 文件
- 根据任务编号找到对应的任务条目
- 提取任务信息：
  - 任务ID（如 B-08）
  - 任务名称（去除复杂度和估算信息）
  - 复杂度（如 L, M, S, XL）
  - 估算工时（如 5 PD）
  - 依赖任务（从任务描述或上下文推断）

### 3. 生成分支名
根据任务ID和名称生成分支名：
- 格式：`feature/B-XX-<kebab-case-name>`
- 规则：
  - 任务编号转为小写（B-08 → b-08）
  - 任务名称转为 kebab-case（中文保留拼音或翻译，英文转小写用连字符连接）
  - 移除特殊字符
- 示例：
  - `B-08: 端到端自动化引擎编排` → `feature/b-08-automation-engine`
  - `B-12: 后端 API 响应模型统一重构` → `feature/b-12-api-response-model`

### 4. 创建开发分支
1. 确保当前在 `develop` 分支且工作区干净
2. 拉取最新代码：`git pull origin develop`
3. 创建新分支：`git checkout -b <分支名>`
4. 推送到远程：`git push -u origin <分支名>`

### 5. 生成任务说明书
根据任务说明书模板（参考 docs/tasks/ 目录下的格式）生成内容：

### 6. 创建任务说明书文件
- 文件路径：`docs/tasks/<任务ID>_<任务名称>.md`
- 文件名规则：
  - 任务ID + 下划线 + 任务名称
  - 中文可保留或转换为英文
  - 示例：`B-08_端到端自动化引擎编排.md` 或 `B-08_automation_engine.md`

### 7. 提交初始文件
1. 添加任务说明书：`git add docs/tasks/<文件名>.md`
2. 提交：`git commit -m "docs(<任务ID>): 创建任务说明书"`
3. 推送：`git push`

### 8. 汇报结果
向用户简洁汇报：
- ✅ 任务已启动
- 📋 任务ID：<任务ID>
- 📝 任务名称：<任务名称>
- 🌿 分支名：<分支名>
- 📄 说明书路径：<文件路径>
- 📊 复杂度：<复杂度>（<估算工时>）
- 🔗 依赖：<依赖任务列表>

## 注意事项

- **分支命名**：统一使用 `feature/` 前缀，遵循 kebab-case 规范
- **任务ID**：保持与 TODO.md 一致（如 B-08、FE-01）
- **复杂度评估**：S（1-2 PD）、M（3-4 PD）、L（5-7 PD）、XL（8+ PD）
- **优先级**：默认 P0，核心功能任务；P1 为辅助功能
- **依赖关系**：从 TODO.md 中提取依赖任务，确保任务顺序正确
- **文件编码**：使用 UTF-8 编码，确保中文正常显示
- **日期格式**：统一使用 YYYY-MM-DD 格式

## 任务编号映射

根据 TODO.md，当前任务编号规则：
- **F-XX**: 项目基础（Foundation）
- **B-XX**: 后端任务（Backend）
- **FE-XX**: 前端任务（Frontend）
- **T-XX**: 测试任务（Testing）
- **D-XX**: 文档与发布（Documentation）

示例执行：
```bash
start-task B-08
```

将自动：
1. 从 TODO.md 提取 B-08 信息
2. 创建分支 `feature/b-08-automation-engine`
3. 生成 `docs/tasks/B-08_端到端自动化引擎编排.md`
4. 提交初始文件
