## 二、目标与范围（Scope）
- 目标：实现可复用的标题解析核心，覆盖主流国漫/番剧资源命名，输出结构化字段供 Torznab XML 生成与编排直接消费。
- 范围：
  - 解析输入：种子/磁链标题（必填），可选 indexer/source/provider 元信息。
  - 覆盖 ≥5 类常见命名格式：`SxxEyy`、`第xx话/集/卷`、`EPxx`、`xxEND/完结/全集`、连播 `xx-yy`、含别名/多语言标签（简/繁/国粤）、含 4K/HDR/AV1/HEVC/组名等。
  - 提取字段：剧名（原始 & 规范化）、匹配别名、季（缺省 1）、集数列表与区间、特殊标记（SP/OVA/番外/预告）、版本号（V2+）、分辨率/来源/编码/HDR/音轨/字幕语言、发布组、是否完结、置信度、未解析残留。
  - 输出统一元组 `(success: bool, data_or_error)`；成功返回 `ParsedTitle` 结构，失败返回可读错误字符串。
  - 提供解析服务封装（模块/类/函数），供 B-07/B-08 直接调用；保持异步友好（可在同步实现外留异步包装）。
  - 结合 TMDB 统一结构：接受可选 `tmdb_candidates`（搜索结果）、`tmdb_alternative_titles`（别名列表），按地区优先级 CN > HK > TW > 默认，做标题/别名的模糊匹配与置信度加权。
- 非范围：
  - Torznab XML 生成（B-07）、编排与落库（B-08）。
  - 前端 UI/配置页面改动。
  - 长期缓存/数据库持久化（放入 B-08）。

## 三、输入输出契约
### 3.1 输入结构（建议）
- `raw_title: str`（必填）：种子/磁链名称。
- `source: str | None`：来源标记，如 `prowlarr`、`rss`、`manual`。
- `indexer: str | None`：索引器名称或 ID。
- `tmdb_candidates: list[TMDBSearchItem] | None`：B-04 统一搜索结构，可为空。
- `tmdb_alternative_titles: list[TMDBAltTitle] | None`：B-04 统一别名结构，可为空。
- `language_pref: list[str]`：默认按配置 `zh-CN` → `zh-TW` → `ja` 回退。

### 3.2 输出结构（`ParsedTitle` 建议字段）
- `raw_title: str`：输入原文。
- `normalized_title: str`：去噪/统一符号后的标题文本。
- `matched_title: str | None`：与 TMDB/别名匹配到的标题；未匹配则为 `None`。
- `tmdb_id: int | None`：若匹配到候选，带出 ID 便于后续写入 Torznab。
- `season: int | None`：缺省 1，未出现季信息可为空。
- `episodes: list[int]`：解析出的集号（包含连播拆分）。
- `episode_range: tuple[int, int] | None`：如 `01-02` 连播；单集可与 `episodes` 对齐。
- `special_type: str | None`：`SP` / `OVA` / `OAD` / `Trailer` 等特殊标记。
- `is_finale: bool`：`END/完结/全集` 标记。
- `resolution: str | None`：`2160p|1080p|720p|480p` 等。
- `source: str | None`：`WEB-DL|WEBRip|BluRay|HDTV|DVDRip` 等。
- `hdr: str | None`：`HDR|HDR10|HDR10+|DolbyVision`。
- `codec: str | None`：`H264|H265|HEVC|AV1|x264|x265`。
- `audio: str | None`：`AAC|AC3|EAC3|FLAC|DTS(-HD)|TrueHD`。
- `subtitle_lang: list[str]`：`chs|cht|chs&cht|eng` 等。
- `release_group: str | None`：如 `LoliHouse`、`Lilith-Raws` 等。
- `version: str | None`：`V2/V3` 等重发标记。
- `tags: list[str]`：如 `NC-OP/ED`、`NC`、`合集`、`国粤双语`。
- `confidence: float`：0~1，基于命名模式覆盖度、别名匹配、字段完整度计算。
- `unparsed_segments: list[str]`：未识别的残留文本，便于调试或日志。

### 3.3 返回格式
- 成功：`(True, ParsedTitle)`；
- 失败：`(False, "标题解析失败: <原因>")`；原因需包含缺失信息或不支持的格式提示。

## 六、解析策略与算法要点
1. **预处理**：
   - 统一分隔符（空格/点/下划线/中括号/顿号），中文数字转阿拉伯（如 一→1）。
   - 规范季/集关键字别名：`季/Season/S`，`集/话/話/Ep/EP/E`，`完结/END/全集` 等。
   - 提前提取发布组（前后括号/结尾 `-Group`）。

2. **模式识别顺序**：
   - 季集强模式：`S\d{1,2}E\d{1,3}`、`S\d{1,2}\s?-?\s?EP?\d+`。
   - 中文集数模式：`第\d+(集|话|話)`、`\d+话`、`\d+集`。
   - 连播/区间：`(\d{2,3})-(\d{2,3})`、`\d+~\d+`。
   - 特殊标记：`SP|OVA|OAD|PV|NCOP|NCED|Trailer`。
   - 完结标记：`END|完结|全集|FIN|END\.\d+`。
   - 版本/重发：`V2|V3|REPACK|Proper`。

3. **质量/格式提取**：
   - 分辨率：匹配 `2160p|4K|1080p|720p`（4K 归一 2160p）。
   - 来源：`WEB-DL|WEBRip|WEBrip|BDrip|BluRay|HDTV|DVDRip|TVRip|B-Global|Baha` → 统一枚举。
   - HDR：`HDR|HDR10|HDR10+|Dolby.Vision|DV`。
   - 编码：`AV1|HEVC|H265|H264|x265|x264`；音频：`AAC|AC3|EAC3|FLAC|DTS(-HD)|TrueHD`。
   - 字幕语言：`简体|繁体|简繁|CHS|CHT|BIG5|GB|内封|內封` → 归一为 `chs|cht|chs&cht`。

4. **别名匹配与置信度**：
   - 使用 B-04 提供的 `tmdb_alternative_titles`，按地区优先级匹配；命中则补 `tmdb_id`、`matched_title` 并提升 `confidence`。
   - 无 TMDB 数据时，基于标题 token 重合度与模式完整度计算置信度；缺失季/集/质量信息时降低分值。

5. **容错与残留**：
   - 允许部分字段缺失仍返回成功（如仅识别剧名+集数），将未识别片段写入 `unparsed_segments` 便于日志。
   - 对无法识别的标题返回 `(False, reason)` 并附加简单建议（如“缺少集数”）。

6. **结构与扩展性**：
   - 建议路径：`backend/app/services/parser/title_parser.py`（核心逻辑） + `backend/app/services/parser/models.py`（数据模型）。
   - 核心函数：`parse_title(raw_title, tmdb_candidates=None, tmdb_alternative_titles=None, language_pref=None) -> tuple[bool, ParsedTitle | str]`。
   - 为异步编排准备：可提供 `async_parse_title` 包装以便 B-08 在协程内调用。
   - **配置化/字典驱动**：通过系统字典管理维护枚举与规则，解析器从 DB 拉取映射和正则：
     - 字典类型建议：`title_parser.resolution/source/hdr/codec/audio/subtitle/tag/rule`。`value` 存标准化输出，`extra_data.aliases` 提供多重匹配 token。
     - 规则（rule）字典项：`code`=目标字段（如 resolution/source/hdr/codec/audio/subtitle_lang/tag/release_group/version/special_type/is_finale），`extra_data.pattern` 正则、`priority` 排序、`enabled` 开关，`value` 为命中后写入的值（追加或覆盖），`extra_data.kind` 标识 `builtin/user`。
     - 新增加载器 `backend/app/services/parser/config_loader.py`，封装 `load_parser_config(db)`，输出 `ParserConfig`（映射+规则）；解析器接受 `config` 注入以支持热更新。
     - 规则执行路径：DB 枚举/规则优先，未配置时使用内置兜底；支持通过字典管理维护内置/用户项（`extra_data.kind=builtin/user`），用户项可覆盖同 token。

## 九、风险与对策
- 命名差异大/含大量非标准符号 → 预处理阶段扩充符号映射与正则，保留 `unparsed_segments` 便于回溯。
- 别名缺失导致匹配失败 → 通过 TMDB `alternative_titles` 多地区兜底；提供最小置信度阈值，必要时允许人工映射表（后续 B-08 落库）。
- HDR/音轨标记不一致（如 DoVi/DV/DolbyVision） → 做多别名映射并统一输出枚举。
- 多版本/重发（V2/REPACK）与组名位置多变 → 在预处理阶段先截取组名与版本，减少干扰。
